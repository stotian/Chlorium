# Native atlas uploads and final quads

**Status: proposed; research only, 2026-10-21.** Target: GD 2.2081 / Geode 5.11.2. Preserve every native update, pixel input, draw position, shader and post-effect. Local SDK declarations are authoritative for ABI; upstream Cocos 2.2.3 explains behavior but does not prove RobTop's modified function bodies.

## Native contract

- A visible batch's `visit()` surrounds drawing with its matrix/grid handling, sorts children, applies the batch transform, then draws. An invisible batch returns before that work. Its `draw()` sets up its shader, updates root sprites recursively, applies blending, then invokes the atlas. Sorting updates atlas indices and moves the matching quads/descendants; preserve that order instead of sorting by object ID or material. [Official batch implementation](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/sprite_nodes/CCSpriteBatchNode.cpp#L121-L155), [sorting and drawing](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/sprite_nodes/CCSpriteBatchNode.cpp#L230-L378).
- Dirty sprite transforms produce **batch-local** positions including ancestor sprite transforms and vertex Z, then write their atlas slot. Hidden sprites become degenerate quads. UVs already include animation frame, crop, rotation and flips. Color updates write final RGBA bytes, including native opacity multiplication/rounding, directly into the atlas; sprite transform dirtiness alone therefore misses color changes. [Official sprite implementation](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/sprite_nodes/CCSprite.cpp#L294-L495), [color updates](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/sprite_nodes/CCSprite.cpp#L827-L855).
- The SDK vertex is 24 bytes: position `float3`, RGBA bytes, UV `float2`; a quad is 96 bytes in **TL, BL, TR, BR** order. Preserve all four colors/Z values. Native triangle indices are `0,1,2,3,2,1` per quad. [Geode 5.11.2 types](https://github.com/geode-sdk/geode/blob/v5.11.2/loader/include/Geode/cocos/include/ccTypes.h#L260-L306), [official indices](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/textures/CCTextureAtlas.cpp#L203-L224).
- Read public `m_pQuads` through a const view: upstream `getQuads()` itself marks the atlas dirty. The SDK exposes vertex/index VBO names, dirtiness, total count and capacity. Windows headers select non-VAO atlas rendering by default, and exact bindings mark `setupVBOandVAO` absent on Windows. [Official getter](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/textures/CCTextureAtlas.cpp#L87-L92), [local SDK atlas fields](C:/Users/stoti/Projects/gd-timing-lab/deps/geode-sdk/loader/include/Geode/cocos/textures/CCTextureAtlas.h), [local configuration](C:/Users/stoti/Projects/gd-timing-lab/deps/geode-sdk/loader/include/Geode/cocos/include/ccConfig.h).

## Decision and data flow

| Option | Decision |
|---|---|
| Compare final native quad bytes; upload changed ranges into the **same native VBO**; keep native draw | First implementation: changes transport only; retains all 2.2 effects automatically. |
| Replace an atlas range draw with GPU-cullable native quads | Later extension: requires a separate draw/state equivalence proof. |

```text
native game updates -> native visit/sort/updateTransform -> final atlas bytes
  -> exact changed-block uploads into native VBO -> original native atlas draw
```

**Upload contract.** Hook the two-argument atlas range draw, initially only `start == 0`, `n == totalQuads`, valid bounds and identified storage. Upstream non-VAO drawing uploads that byte range when dirty; its VAO branch instead orphans/maps storage and contains unusual `n-start` sizing, so nonzero starts remain native. Resize can recreate storage under the same VBO name. [Official upload paths](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/textures/CCTextureAtlas.cpp#L549-L635), [allocation/resize](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-2.2.3/cocos2dx/textures/CCTextureAtlas.cpp#L417-L484). The CPU audit reports installed Windows DLL disassembly confirming non-VAO `glBufferSubData`: range draw RVA `0xA6350`, vertex VBO at `+0x40`, dirty flag `+0x48`, quads `+0x60`, offset `start*96`, length `n*96`.

Keep a private byte shadow per atlas/storage/context. A dirty native upload establishes coverage only for its requested quads; an initially clean draw proves nothing. Per-quad coverage bits reject unknown or partially covered spans. A changing active count does not erase existing GPU bytes. Compare blocks exactly, merge adjacent changed blocks and submit original bytes to the original VBO. Never use hashes alone. Preserve the generic array-buffer binding. Initialization, `setQuads`, `resizeCapacity`, foreground recovery and destruction invalidate shadows. Unknown identities and draw hooks retain native behavior. Buffer IDs/sizes alone cannot identify arbitrary external same-size reallocation; interoperability with such mutations is unproven.

The implementation accepts checked `start,n` ranges, tracks only an observed prefix rounded to 256 quads, admits uploads from 4 KiB, limits changed ranges to 32 and uses native uploads for dense changes. The total byte-shadow/coverage allocation is bounded to 32 MiB and 256 atlas entries. The 64 KiB/full-prefix prototype never engaged on the measured level. The current level has not exercised nonzero-start draws; those cases still need live coverage beyond CPU range-planner checks.

**Windows empty-function alias bug (21 October).** In the installed DLL, `CCDirector::purgeCachedData` is the empty `ret 0` stub at RVA `0x1fb0`, shared with unrelated exports. Registering an unconditional hook on it repeatedly cleared the shadow cache during ordinary engine activity. Removed that hook completely. Atlas lifecycle hooks and identity checks remain responsible for invalidation. Before the correction: thousands of captures, zero live shadow bytes and zero avoided uploads. After correction: live shadows, partial/unchanged uploads and 12 exact native-VBO readback checks in the authorized level, with zero mismatches. This byte check does not establish universal rendered-output equivalence.

**Later quad drawing.** Keep the native batch visible and intercept only its atlas submission after native preparation, at the same scene traversal position. Reuse final bytes, native topology, active shader/MVP, texture sampling, blending, framebuffer, scissor/depth/stencil and post-effect boundaries. Do not apply HSV/group/audio effects a second time. Handle `start,n` as a range; never merge across native calls/state changes. Custom vertex shaders or unproven RobTop behavior retain the original draw.

**Evidence gate.** Validate the installed binary contract and generated ABI guards, then compare native-VBO bytes and rendered output across color-only updates, animations, hidden descendants, reorder/remove/resize, partial draws and context recovery. Audit RobTop's manual-sort/vertex-mod behavior before replacing draws. Measure CPU comparison cost and uploaded bytes separately. This design is not a claim of validated general visual equivalence or an in-game speedup.
